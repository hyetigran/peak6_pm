# Bind to the canonical OpenBook deployment with monitored identity

Supersedes ADR-0029, which M0 evidence invalidated: OpenBook v1.7 compiles its program ID into the executable (`declare_id!`), anchor rejects every instruction at any other address, and the ID is embedded at least twice — once inlined in code — so no binary patch can be proven complete and building from modified source would require `enable-gpl` and abandon the official artifact (`docs/adr/openbook-v2-pin.md` §7). The pinned official bytes and executable immutability are therefore jointly unsatisfiable on devnet.

V1 binds to the **canonical devnet deployment** `opnb2LAfJYbRMAHHvqjCwQxanZn7ReEHp1k81EohpZb`, proven byte-identical to the official v1.7 artifact (SHA-256 `a3eb0fad…`, deployment slot `282042596`), and treats its retained external upgrade authority (`Cax5s8Cj…`) as a **monitored, fail-closed risk** instead of requiring `upgrade_authority == None`. `initialize_config` snapshots the program ID, ProgramData address, deployment slot, and executable hash; every OpenBook CPI re-verifies the ProgramData identity and exact stored slot while holding the account read lock, so any upgrade makes Meridian halt fail-closed — an availability loss, never fund exposure to unverified code. Automation alerts on any change to the deployment's slot, authority, or account state, and a verified upgrade event reopens the architecture rather than being adopted in place. This revises the G1 immutability clause of PRD v0.7 (a stakeholder-approved change, 2026-08-20); every other G1 requirement — byte verification against the official artifact, license boundary, pinned-source facts, golden tests, per-CPI checks — stands unweakened. The ADR-0029 deployment `923gY…` is permanently inert and must never be referenced. Localnet loads the pinned artifact at the canonical ID so every environment shares one address.
